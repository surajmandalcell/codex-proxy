Desktop multi-provider AI gateway

One local API for all your AI providers.

Add OpenAI, Anthropic, Gemini, Grok, compatible HTTP, command, or module accounts. The desktop app routes each request to an eligible account, fails over before streaming starts, and records usage locally.

Quick start Download latest

Runs on your machine. The server binds to loopback by default. No hosted control plane is required.

01

What the desktop app does

Configuration, credentials, routing state, and usage data stay on the local machine.

01

Connect providers

Add multiple accounts per provider with independent priority, weight, enabled state, cooldown, and local limits.

02

Expose one local API

Use OpenAI Chat Completions, OpenAI Responses, Anthropic Messages, model discovery, token estimation, and health routes.

03

Route and fail over

Select an eligible account by policy and retry rate limits, overloads, network errors, or timeouts before output starts.

04

Record local usage

Store tokens, cache activity, latency, first-token latency, estimated cost, status, and route attempts in SQLite.

03

Routing and failure handling

Set one global policy, optionally override it per provider, and keep every route inside explicit eligibility rules.

  1. 01Priority
  2. 02Round robin
  3. 03Weighted random
  4. 04Least in-flight
  5. 05Lowest recent latency
  6. 06Lowest estimated cost
  7. 07Sticky session

Eligibility

Provider and account state, model globs, local limits, cooldown, and attention state.

Temporary isolation

Retry-After and exponential cooldowns exclude routes after rate limits and transient failures.

Streaming boundary

A request never switches providers after text or tool activity reaches the client.

05

Security boundaries

Security controls are enforced in the Electron main process and local HTTP server.

Credential storage

Electron safeStorage is used when available, with AES-256-GCM fallback encryption.

Renderer isolation

Context isolation and sandboxing are enabled; Node integration is disabled.

Network scope

The server rejects non-loopback bind addresses and uses exact-origin CORS.

Logging

Credential-shaped fields and bearer values are redacted before logs are stored or shown.
