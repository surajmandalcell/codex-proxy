Desktop multi-provider AI gateway

Use your AI providers through one local gateway.

Connect Claude, Codex, Z.ai, and other supported providers. Proxy-Inator gives local clients OpenAI-compatible and Anthropic-compatible routes.

It selects routes, changes routes before output starts, and records usage on your computer.

Quick start Download latest

The server listens on loopback by default. The app does not need a hosted control plane.

01

Desktop functions

The app keeps configuration, credentials, route state, and usage data on the local computer.

01

Connect providers

Add multiple accounts to each provider. Set priority, weight, enabled state, cooldown, and local limits.

02

Serve one local API

Use Chat Completions, Responses, Messages, model, token-estimate, and health routes.

03

Route and fail over

Select an eligible account. Try another route after a temporary failure and before visible output.

04

Record local usage

Store token, cache, latency, cost, status, and route-attempt data in SQLite.

Routing and failure control

Set one global strategy. Add a provider strategy only when it is necessary.

Eligibility

Check provider state, account state, model globs, local limits, cooldown, and attention state.

Temporary isolation

Use `Retry-After` or an increasing cooldown after a temporary failure.

Visible-output boundary

Do not change providers after text or tool output reaches the client.

OpenAI-compatible client 
export OPENAI_BASE_URL=http://127.0.0.1:8081/v1
export OPENAI_API_KEY=local-proxy-key
One gateway for different clients

OpenAI-compatible clients use the base URL above. Anthropic-compatible clients use /v1/messages.

05

Security boundaries

The Electron main process and local HTTP server apply the security controls.

Credential storage

Use Electron safeStorage when it is available. Otherwise, use AES-256-GCM.

Renderer isolation

Use context isolation and sandboxing. Do not enable Node.js integration.

Network scope

Reject non-loopback hosts. Use exact CORS origins.

Logs

Remove credential fields and bearer values before you store or show logs.
